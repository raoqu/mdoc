# 文档发布与 Hugo 主题

发布源是当前知识库 SQLite 中的文档，不扫描项目中的 `docs/`、源码、旧 `public-site/` 或整个附件目录。默认使用与 `~/mylab/blog` 相同的 Stack v3.31.0，通过 Hugo Modules 单独安装主题，项目内编译的 Hugo Extended 引擎负责实际生成站点。Hugo v0.130.0 的运行时源码位于 `third_party/hugo/`，通过本地 Go module replace 编译进 Mdoc，修改该目录中的源码会直接改变发布行为。

## 1. 标记与发布

在笔记右侧的详情栏勾选“标记为发布”，等自动保存完成后，点击左下角知识库名称，再点击对应知识库右侧的“发布配置”（也可打开“设置 → 文档发布”）。选择其他知识库的入口时，会切换到该知识库并打开它的配置。

在“发布服务器”中分别填写 **Server IP**（IPv4 地址或主机名）、**SSH 用户**（可留空使用 SSH 默认用户）和**发布目录**（服务器上的绝对路径，例如 `/var/www/notes/`），然后点击“保存配置”。配置按知识库独立保存；不同知识库应使用不同的发布目录。已有 `user@host:/目录/` 配置会自动拆分显示，配置文件和 CLI 继续使用 `deployTarget` 字段。

保存配置并安装主题后，可直接点击左侧栏顶部、收起按钮旁的发布图标，一键构建并发布当前知识库。发布期间图标旋转，按钮和知识库切换暂停使用；完成后 toast 显示知识库名称和发布文档数量，失败时显示原因。未配置服务器或未安装主题时，会打开发布配置页提示补全。笔记尚未保存或存在保存冲突时，发布按钮暂停使用。

发布图标右侧的眼睛按钮“预览当前知识库”会使用当前 Hugo 主题，按相同的发布规则生成本地站点并在新标签页打开。预览无需填写服务器配置；生成期间按钮显示加载状态，并暂停发布和知识库切换。主题未安装时会引导到发布配置，笔记尚未保存或存在冲突时需先完成保存。

也可以直接写入 YAML frontmatter：

```markdown
---
publish: true
title: 对外文档
tags: [使用说明]
categories: [产品]
---

# 对外文档

这里是正文。
```

发布规则：

- 只有 YAML 布尔值 `publish: true` 才会进入站点，缺省、`false`、字符串 `"true"` 和无效 YAML 都不发布。
- 私密标记（数据库字段或 frontmatter）、回收站文档、`draft: true` 始终排除。
- 标记写在 Markdown 内，已有的保存、导入、导出和 Git 备份都会保留它。
- 发布范围覆盖当前知识库内的各笔记空间；切换知识库后使用独立的配置与构建目录。
- 取消发布、删除或设为私密后，再次执行“发布到服务器”，才会从线上撤下。即使发布清单为空，也会同步空站点以撤下旧内容。

页面中的“待发布文档”显示实际符合条件的文档。主题安装、生成预览和部署是独立操作。部署每次从数据库重新筛选和构建，不会同步旧版的全量输出。

## 2. 环境与主题安装

生产 Mdoc 已内置 Hugo 的页面、模板、资源与 Sass 构建代码，无需另外安装 Hugo。编译 Mdoc 需要 Go、CGO 与 C/C++ 编译器（macOS 可使用 Xcode Command Line Tools）；首次安装主题需要 Go 和网络。部署使用本机 `rsync`、`ssh` 及现有 SSH 密钥，远端不需要 Go、Node.js、Hugo 或 SQLite。

```bash
./publish.sh config deploy/publication.example.json
./publish.sh theme install
./publish.sh build
./deploy.sh
```

使用生产二进制时，对应命令是：

```bash
./mdoc publish config deploy/publication.example.json
./mdoc publish theme install
./mdoc publish build
./mdoc publish deploy
```

命令失败会返回非零退出码。仓库脚本默认运行当前 Go 源码，也可指定 `MDOC_BIN=/absolute/path/mdoc`。`DEPLOY_TARGET` 或 `./deploy.sh user@host:/var/www/notes/` 只覆盖这次部署的目标。

主题配置示例：

```json
{
  "theme": "stack",
  "treeTheme": "default",
  "title": "墨笺文档",
  "baseURL": "https://mdoc.raoqu.cc/",
  "subtitle": "公开的笔记与文档",
  "themeModule": "github.com/CaiJimmy/hugo-theme-stack/v3",
  "themeVersion": "v3.31.0",
  "includeTOC": true,
  "deployTarget": "root@10.6.0.1:/www/wwwroot/mdoc/"
}
```

更换主题模块或固定版本后，单独执行主题安装，再生成预览。安装由内置 Hugo `modules` 包执行，生成独立的 `go.mod`、`go.sum` 与主题 `_vendor/`；它不修改 Mdoc 的 Go 依赖或博客。后续构建使用已安装的 vendor，不自动升级主题。Stack 的搜索、归档、明暗切换、标签和目录已配置；其他原生 Hugo Module 主题可使用下面的覆盖目录调整布局。

当前知识库的发布目录可从 `GET /api/publication` 的 `directory` 字段查看：

```text
~/.mdoc/publishing/
  themes/<模块与版本的哈希>/    # 单独安装的主题
  <知识库路径的哈希>/
    config.json                # 站点及服务器配置
    overrides/                 # 可选的 Hugo layouts、assets、i18n 覆盖
    current/
      public/                  # 唯一部署内容
      preview/                 # baseURL=/site/ 的本地预览
      manifest.json            # 本地构建信息，不上传
```

例如在 `overrides/layouts/partials/footer/custom.html` 自定义 Stack 页脚。覆盖文件优先于主题；覆盖自带的 Mermaid 页脚钩子时需自行保留 Mermaid 脚本。文件 / 文件夹预览、知识库单篇预览与发布共用 `themes/<主题名>/` 下的 Hugo 主题包。目录树由独立的 `mdoc/tree.html` 组件渲染；主题选择、继承和扩展方式见 [THEME.md](THEME.md)。

发布导航来自侧栏“已固定”文档的可拖拽树。目录只显示满足发布规则的节点；不公开的父节点会被移除，符合条件的子节点提升到同级。公开但未固定的文章仍会发布。删除或取消固定父节点时，其子节点按原顺序提升，树结构保存到当前知识库。

## 3. 内容与附件

站点使用文档 ID 的哈希生成稳定路径，重命名不改变 URL。同名文档不会互相覆盖。`[[文档名]]`、`[[ID|文字]]` 和已发布文档的别名可生成站内链接；无法唯一匹配或未发布的目标仅保留文字，不会将目标内容加入站点。普通 Markdown 链接保留原始目标，引用本地 `.md` 时建议改成双链或目标站点 URL。

仅复制已发布正文中的 Markdown 图片、链接及 `image` 封面所引用的 `/uploads/` 或 `/audio/` 文件，作为 Hugo 页面资源。未引用附件、数据库、备份、分享页及项目文件不上传。缺失附件、路径穿越和符号链接会使构建失败，避免上线不完整站点。图片上传后的原始 HTML 不属于附件收集入口；站点不渲染 Markdown 中的原始 HTML。

保留的公开 frontmatter 字段包括标题、日期、描述、标签、分类、关键词、权重、数学公式、目录、许可和封面。`private`、`publish` 及其他内部字段不输出；Hugo 的 `url`、`aliases`、`_build` 等字段不会被原样透传。搜索索引、RSS、归档和站点地图全部基于同一份筛选结果。

Stack 支持 GFM、代码高亮、KaTeX 与 Mermaid；数学公式及 Mermaid 的浏览器脚本使用主题/渲染器配置的 CDN。站点构建在 Mdoc 进程内执行，不调用外部 Hugo、Sass 或 Go 程序；构建期间禁止主题启动外部程序。

## 4. 服务器与 Caddy

部署目标为 `root@10.6.0.1:/www/wwwroot/mdoc/`，域名为 `https://mdoc.raoqu.cc/`。`deploy/mdoc.caddy` 对应服务器上的 `/www/server/conf/mdoc.caddy`：

```caddyfile
mdoc.raoqu.cc {
    root * /www/wwwroot/mdoc
    encode zstd gzip
    file_server
}
```

服务器主配置 `/www/server/Caddyfile` 已使用 `import conf/*.caddy`。首次配置后，在服务器验证完整配置并重新加载：

```bash
/www/server/caddy validate --config /www/server/Caddyfile
/www/server/caddy reload --config /www/server/Caddyfile
```

部署通过 `rsync --checksum --delete-delay --delay-updates` 增量传输。服务器目录应专用于本站，因为撤下操作会删除该目录中本次构建不存在的文件。构建和预览都成功后才会调用 rsync；失败会保留上次本地构建。网络中断可能使远端更新不完整，修复后重新部署即可；此流程不是远端整站原子切换。

管理端 `/site/` 提供本地预览。若使用独立只读服务，将构建命令返回的 `output` 路径传入 `SITE_DIR`；服务器推荐直接使用上述 Caddy 静态托管。

## 5. 实现与验证

- `third_party/hugo/`：实际纳入项目的 Hugo 运行时源码，含页面模型、模板、模块挂载和资源管线。
- `internal/hugoengine/engine.go`：项目内的构建生命周期、配置隔离、静态资源合并、日志和取消控制。
- `publication.go`：配置、主题安装、内置引擎构建、预览与 rsync 部署。
- `publication_export.go`：发布筛选、frontmatter 白名单、双链与附件投影。
- `publication_cli.go`：与界面共用实现的命令行入口。
- `publication-settings.tsx`：发布管理页面。

HTTP 接口：`GET/PUT /api/publication`，`POST /api/publication/theme`、`/build`、`/deploy`。旧的 `POST /api/build` 也进入相同的筛选与 Hugo 构建流程。文件锁防止 CLI 与管理端同时写发布目录；长任务固定数据库连接，避免知识库切换混用文档。

```bash
go test -tags extended ./internal/hugoengine
go test -tags extended ./cmd/mdocman -run Publication
MDOC_TEST_THEME_INSTALL=1 go test -tags extended ./cmd/mdocman -run Publication -count=1
```

引擎测试清空 PATH，验证没有外部程序时仍可完成主题渲染和 Sass 编译。最后一条在独立临时知识库中安装 Stack，验证隐私筛选、附件范围、子路径链接、撤下清理及模板错误不部署。首次主题安装需要网络；已安装主题的站点构建不需要 Go 或 Hugo。

Hugo 源码版本、上游 commit、许可与本地 Context 改动见 [源码来源说明](../third_party/hugo/MDOC-UPSTREAM.md)。保留原生 `extended` 构建标签，项目脚本会自动传入；直接使用 Go 命令时须加 `-tags extended` 以启用 Stack 所需的 Sass 编译。

参考源码：Hugo v0.130.0 的 [`modules/collect.go`](https://github.com/gohugoio/hugo/blob/v0.130.0/modules/collect.go) 中的模块收集、vendor 优先级与组件挂载；使用官方 [Hugo Modules](https://gohugo.io/hugo-modules/use-modules/) 安装流程。默认版本、主题选择与 rsync 管理方式取自本机 `~/mylab/blog` 的 `go.mod`、`config/_default/` 和 `deploy.sh`。
