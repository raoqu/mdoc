# Mdocman 使用说明

Mdocman 是一个使用 Go、TypeScript 和 SQLite 构建的 Markdown 笔记管理与静态发布工具。它包含管理端和只读发布端，适合管理多个笔记本，并以类似 Hugo 的方式生成可部署静态页面。

## 1. 启动开发环境

需要安装 Go 1.24、Node.js 22 和 pnpm 11。

```bash
./dev.sh
```

脚本会同时启动：

- 启用了 HMR 的 TypeScript 管理界面，修改前端代码后页面会自动热更新；
- Go 管理端 API，默认端口为 `8080`；
- `/api`、`/uploads`、`/s` 和 `/site` 开发代理。

自定义管理端口：

```bash
API_PORT=9090 ./dev.sh
```

按 `Ctrl+C` 可同时停止前后端。

## 2. 笔记本与多级目录

- 左侧底部显示当前知识库，点击可切换、调整颜色、在 Finder 中定位或新建知识库。
- 所有知识库都保存在固定的 `~/.mdoc/` 数据目录，重启后恢复上次选择。
- 点击“新建目录”可以创建根目录。
- 点击目录右侧的 `＋` 可以创建子目录。
- 目录节点可以拖到其他目录中，以改变父子层级。
- 将目录拖到“多级目录 · 拖到这里移至根级”区域，可将其移回根目录。
- 系统会阻止将目录拖入自身或自己的子目录。
- 文档同样可以拖到任意目录中。
- 更改会自动写入当前选中的知识库。

## 3. Markdown 编辑

编辑器支持 Markdown 源码和渲染预览两种模式。工具栏可以快速插入：

- 标题与粗体；
- GFM 表格；
- 围栏代码块；
- 数学公式；
- Mermaid 图表；
- 本地图片。

代码块示例：

````markdown
```go
fmt.Println("Hello")
```
````

数学公式示例：

```markdown
$$
E = mc^2
$$
```

Mermaid 图表示例：

````markdown
```mermaid
graph LR
  A[开始] --> B[完成]
```
````

上传的图片保存在 `~/.mdoc/uploads/`，发布静态站点时会自动复制。

在编辑器中拖动图片右下角的手柄可以按原始宽高比调整尺寸。选中图片时会出现
仅包含“恢复默认大小”“添加/修改链接”和“删除图片”的工具栏；点击图片以外区域
后工具栏自动关闭。尺寸使用标准 Markdown 图片后的 HTML 注释保存，例如：

```markdown
![示意图](/uploads/example.png)<!-- {"width":640,"height":360} -->
```

不识别尺寸信息的 Markdown 查看器仍会按普通图片显示，并忽略不可见的 HTML 注释；
墨笺重新打开时会读取注释并恢复可编辑尺寸。

图片工具栏的链接按钮会把目标地址写入同一段元数据，图片在编辑器中仍保持图片
形态；浏览器预览和静态发布会把它渲染为可点击图片。按住 `⌘`/`Ctrl` 点击编辑器
中的图片也可打开链接。

笔记顶部的预览按钮会将当前编辑内容提交给本机 Go 服务的
`/api/preview/<文档 ID>` 端点，并在新浏览器标签中实时渲染；无需先保存或发布。
预览会服务端高亮常见编程语言的围栏代码块（基于 Chroma），并将 ` ```mermaid ` 代码块
在浏览器中渲染为图表（通过 jsDelivr 加载 Mermaid；离线时仍显示源码）。
鼠标悬停在 Mermaid 图表上时会出现放大按钮，点击后可在浮层中预览；浮层默认占满画布并
将图表适应到可视区域，支持滚轮缩放、按钮缩放、拖拽平移，按 `Esc` 关闭。双击图表
也可打开浮层；工具栏「适应」或快捷键 `0` 可重新适应画布。
预览页右上角默认只显示一个主题图标；点击图标后，可在弹出菜单中切换默认、护眼、
暗色和雅黑紧凑主题。选择结果保存在浏览器本地，后续打开预览时会自动恢复。
“雅黑紧凑”在 Windows 上优先使用微软雅黑，在 macOS 上回退到苹方，并继续回退到
思源黑体等常见中文无衬线字体；正文采用 14px 字号与 16px 总行高，表格、代码和
引用采用 12px 字号与 14px 总行高。

预览主题配置位于项目根目录的 `themes/`。`default.css` 是完整的默认 skin，统一定义
背景色、字体颜色、各级标题字体、正文与行间距、表格字体与行间距、代码及引用字体
与行间距等 CSS 变量；其他主题可以只覆盖需要调整的变量。新增 CSS 文件后，还需在
`cmd/mdocman/preview_theme.go` 的 `previewThemes` 列表中登记主题 ID 和显示名称。

## 4. 导入和导出

点击“导入目录”可以选择包含 Markdown 文件的目录。系统会：

- 只导入 `.md` 文件；
- 保留原目录的多级结构；
- 将内容写入当前笔记本的 SQLite 数据库。

点击“导出 ZIP”可以导出当前笔记本。压缩包中保留笔记本、目录和 Markdown 文件的层级关系。

## 5. 单页链接分享

打开需要分享的文档，然后点击顶部的“分享链接”。系统会：

1. 保存文档的最新内容；
2. 生成一个不可预测的随机 ID；
3. 生成不包含笔记目录的独立静态页面；
4. 自动复制分享 URL。

分享地址格式：

```text
https://notes.example.com/s/随机ID/
```

同一文档重复点击分享时会复用原来的随机 ID。分享关系保存在 SQLite 的 `shares` 表中，不会因为再次保存笔记而丢失。

## 6. 静态发布

“发布含目录”决定普通静态笔记页面是否显示左侧文档目录。单页分享页面始终不显示侧栏。

点击“一键发布”后，管理端会根据 `public-site/.mdocman-manifest.json` 中的 SHA-256 内容哈希执行增量生成：

- 仅重建发生变化的页面；
- 目录导航变化时更新相关页面；
- 删除已经不存在的文档页面；
- 保留没有变化的静态文件。

生成目录为 `public-site/`。

## 7. 生产构建

开发阶段可以把 Markdown 文件或目录作为参数传给 `dev.sh`，脚本会跳过前端构建
并直接启动本地预览：

```bash
./dev.sh ./README.md
./dev.sh ./docs
```

```bash
./build.sh
```

构建产物包括：

- `./mdoc`：项目根目录中已内嵌前端的管理端，也支持本地 Markdown 文件或目录预览；
- `dist/bin/mdocman-site`：只读发布端；

部署管理端时只需复制项目根目录中的 `mdoc`。前端页面和静态资源已经编译进该
二进制文件，目标机器不需要 Node.js 或单独的前端目录。开发时仍使用
`./dev.sh` 启动 Vinext HMR 和 Go API。

启动只读发布端：

```bash
SITE_PORT=8090 SITE_DIR=public-site ./dist/bin/mdocman-site
```

发布端不访问 SQLite，只提供生成后的静态页面和分享页面。

## 8. 增量部署

使用 rsync 将静态文件增量同步到服务器：

```bash
DEPLOY_TARGET=user@host:/var/www/notes ./deploy.sh
```

`--checksum` 用于识别内容变化，`--delete` 会删除远端已经从本地静态站点移除的页面。首次部署前应确认目标目录正确。

## 9. 数据与备份

建议备份以下内容：

```text
~/.mdoc/*.db
~/.mdoc/workspace.json
~/.mdoc/uploads/
~/.mdoc/audio-memos/
```

首次启动新版时，如果 `~/.mdoc/mdocman.db` 不存在，会从启动目录中的旧
`data/mdocman.db` 创建 SQLite 一致性快照，并复制旧附件、音频和
`data/notebooks.json`；旧目录保留不动。

## 10. 清理构建文件

```bash
./clean.sh
```

清理脚本会删除构建产物和开发缓存，但保留 SQLite 数据、上传图片和 `node_modules`。
